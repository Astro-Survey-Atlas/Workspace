## 当前明确卡点

### 1. 全量构建失败

本次交接复验执行 `npm run build`，失败于：

```text
test/e2e/survey-layers.spec.ts(138,5): error TS2322
Type '(type: string, attributes: any) => RenderingContext | null' is not assignable
to HTMLCanvasElement.getContext 的重载类型。
```

原因是测试直接覆盖 `HTMLCanvasElement.prototype.getContext`，返回类型无法满足 `2d`、`webgl`、`bitmaprenderer`、`webgpu` 等重载。可以用 `Object.defineProperty` 安装运行时 wrapper，避免给重载属性直接赋一个窄签名函数；修复后必须重跑全量构建。

### 3. Canvas 降级范围不完整

当前 Canvas fallback 只替代“项目态势”的 `SurveyLayerViewer`。下列路径仍直接创建 WebGL renderer：

所以无 WebGL 浏览器虽然可能看见项目覆盖，继续进入细化或体积模式仍可能再次报错。需要明确产品策略：为这些视图也做 2D fallback，或在无 WebGL 时禁用相应命令并给出明确状态。

### 4. WebGL 预探测需要审查

`webglContextAvailable(targetCanvas)` 会先在实际画布上创建一个 WebGL2 context，然后 Three.js 再使用该画布。需要检查：

- 预探测是否本身消耗 context 配额。
- 探测参数与 Three.js 创建参数不一致时是否有兼容问题。
- 构造异常后替换 canvas 是否完整保留 DOM 属性、事件与测试选择器。
- 是否应改用临时 canvas 探测并立即释放，或只捕获 renderer 构造异常。

### 5. 外部轮询的语义还需补测试

已有测试覆盖“503 保留状态”，但还应覆盖：

- 多个运行记录中一个任务失败不会阻止其他任务刷新。
- 后台 `start()` 不产生未处理 Promise rejection。
- 扫描历史 GET 在 Kubernetes 请求悬挂时仍能立即响应。
- 404、真实 Flink terminal failure 和暂时不可达的语义区别。

## “公开覆盖资源包”的实际进度

这个想法没有进入代码实现。当前仓库只有可复用的基础构件：

- `src/survey-registry.ts` 有内置 survey/release/product/modality 元数据和用户源注册。用户注册只生成 `metadata_only + pending footprint`，不能附加覆盖包。
- `src/survey-footprints.ts` 读取一个全局 `survey-footprints.json` manifest，内容包含 survey/release/product、HEALPix pixels、证据质量和来源 URL。
- 前端可以显示/隐藏已有 footprint，偏好仅存在 `localStorage`；这不是资源包安装。
- `/api/astro/coverage` 已能按资产归属把扫描得到的本地像素分层，前端只高亮这些像素，而不是把整个官方 footprint 当成本地拥有。这部分与用户要求一致。

仍缺少：

- `CoverageResourcePack` manifest/schema：包 ID、版本、survey/release/product/modality 身份、覆盖证据、官方访问入口、许可证、校验和、更新时间。
- 可用包 registry 与 workspace installed state 的分离。
- list/install/uninstall/upgrade API 和持久化。
- 安装包后动态合并 footprint catalog，而不是服务器启动时只读一个全局 JSON。
- 前端“可添加资源”与“已添加图层”的界面。
- 包版本、证据更新、冲突、离线导入和卸载后的状态语义。
- 官方覆盖、本地核验覆盖及二者差集的回归测试。

推荐保持三层状态：

1. 可发现的公开资源包。
2. 当前 workspace 已安装、因此可显示的官方覆盖。
3. 扫描证据证明本地已持有的像素子集。

安装资源包只能改变第 2 层，绝不能制造第 3 层。本地高亮只能来自文件级空间证据，并按相同的 `survey + release + product + modality` 身份关联。
