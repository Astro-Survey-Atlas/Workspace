# Workspace 下载区与 HEALPix 对齐验证

日期：2026-10-09（Asia/Shanghai）。

## 修改与原因

- 下载区外层已经占满网格，但工作区的 18px 横向 padding 和预览的 2px 横向 padding 使内容再次缩进。去掉这两层横向 padding 后，工具栏、预览列表及底部分割线与 DAG 分割线对齐，保留纵向间距和列表内部滚动。
- 点击多图层单元时，旧展开效果包含切向位移，并使用独立于白框的径向层距。两图层合成复现中，彩色片中心分别偏离原单元方向约 2.14° 和 1.65°；三图层时外侧薄片还会超出白框。
- 保留径向展开，取消切向位移，并按当前图层顺序排列。展开薄片、白框、选区提示边界与相机外边界使用同一组实际动画深度；收起从当前深度恢复，避免中途打断造成跳变。每个来源只保留一份选中薄片，背景覆盖仍可淡化显示。图层较多时压缩展开间距，最内层半径不低于 0.05。
- 公共巡天原先没有参与真实薄片拾取，只按单位球推算，因此点击不同显示深度的单元中心可能没有结果。公共巡天、本地资产及展开薄片现在都使用真实几何的 NESTED `nside/pixel`，缝隙按对应显示半径做角向回退。服务端 API 与数据格式不变。

## 验证

- 修复前新增回归检查准确失败：下载内容缩进 18px；公共单元中心悬停无结果；三图层同时出现六份选中薄片，且部分薄片偏到其他 HEALPix 单元。
- `npm run verify` 通过：345 项单元测试通过、2 项跳过；类型检查、server/viewer/CLI 构建与严格 Helm lint/render 均通过。
- 本地浏览器回归 28/28 通过。其中四项使用隔离 Vite 场景直接驱动生产 `SurveyLayerViewer`，检查真实渲染顶点、薄片中心、白框范围、提示边界、图层顺序、显隐切换与 G 模式。覆盖两图层、公开巡天加本地资产、11 图层以及展开和收起的中间帧。
- 下载布局覆盖明暗主题、1440/1024/760 三种视口、48 个长文件名和内部滚动；工作区及工具栏、预览、底部分割线与 DAG 边界误差不超过 1px。
- Dev 页面回归 24/24 通过，使用合成 API 响应，不创建真实下载或扫描任务。几何场景测试针对生产源码运行；线上交付由前端及容器文件哈希确认。
