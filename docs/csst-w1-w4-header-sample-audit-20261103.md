# CSST W1–W4 原始 FITS 头抽样检查（2026-11-03）

本轮新增检查 20 个文件，每组 5 个、各来自不同曝光目录，均直接读取源 FITS 头。W1、W2、W3 各 5 个通过本次头内一致性检查；W4 有 4 个通过、1 个需复核。新增样本未出现此前 815 问题文件那种数万倍像元尺度异常。

这支持继续用通过检查的 CSST 文件做 MVP。这里的“通过”限于所检查的头信息，不代表完成科学定标验证；每组 5 个也不足以估算整组或全库的异常比例。

## 来源和抽样方法

检查的是同一份仿真输出下真正的 `W1_Phot`、`W2_Phot`、`W3_Phot`、`W4_Phot` 四个目录，不是将 wide v2、deep v1、deep v2 资产重命名为 W2–W4。完整私有路径只保存在本地检查证据中。

先通过只读目录列表获取各组的全部曝光目录，再按固定种子 `csst-w1-w4-20261103-fixed-v1` 对目录做 SHA-256 排序，抽取 5 个曝光；目录内再按固定哈希排序选 1 个 FITS。文件在读取头和判定质量之前就已选定，检查后没有换掉可疑样本。W1 排除了此前检查过的 12 个曝光目录。

四组原始头均能读取，所读主 HDU 和科学 IMAGE HDU 的基本字段、数据尺寸与文件长度关系通过检查。20 个文件均有 ICRS / TAN 天球 WCS 和明确目标/观测指向，且均能计算出有限的图像中心。独立手写 TAN 公式与 Astropy 的中心坐标在 1e-9 度内一致。

源文件头读取合计 120 个有界 Range 请求、345,600 字节（337.5 KiB），没有读取科学像素数组或完整文件校验和。对象 ETag 和尺寸与预先选定的清单一致。没有提交扫描、修复、下载任务、部署或索引写入。

## 检查口径

- 比较头中 `PIXSCAL1/2`（角秒/像素）与 CD 矩阵两列向量长度乘以 3600 的值。
- 检查 WCS 可计算性、图像尺寸、ICRS 坐标、中心与目标/指向的距离及四角相对中心的角距。目标/指向与单个探测器图像中心是不同含义，不要求二者相等。
- 本次诊断把名义像元尺度偏差超过 1%，或 CD 两轴夹角偏离 90° 超过 1° 的文件列为“需复核”。这是本批 CSST 头信息的筛查口径，不是 FITS 标准对所有 WCS 的有效性规定；允许仿射变换的 WCS 不会仅因这类偏差自动成为坏文件。
- 在应用同一尺度检查前，用上轮 11 个已确认的严重异常头和 1 个正常对照验证：11 个严重异常全部被识别，正常对照通过。

## 对 MVP 的建议

保留 CSST 作为 MVP 数据来源，先使用本次通过头检查的文件；此前已确认的严重异常 WCS 以及本次 W4 待复核样本应单独标记。生成覆盖前需要增加 WCS 质量检查，保留目标/指向与图像中心各自的坐标依据。

这 20 个样本不能证明 W2–W4 全部文件都正常，也不能推导 W4 的全库异常率为 20%。此前 815 的 11 个异常文件是按问题覆盖倒查得到，属于特定问题样本，不能与本轮独立抽样混合计算总体比例。
